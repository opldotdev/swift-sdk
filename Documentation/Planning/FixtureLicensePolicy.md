# Fixture license policy

Status: Conservative Phase 0 engineering policy pending formal legal review.

This is a repository policy, not legal advice.

## Decision for the initial skeleton

- Original Swift SDK source is MIT licensed.
- Do not copy files from `bsv-blockchain/go-sdk` into this repository.
- Do not copy examples from the local BRC repository until that repository has
  an explicit license or permission is documented.
- Source committed vectors directly from permissive or public-domain original
  authorities where possible, including Bitcoin Core, BIPs, NIST, and
  dependency-owned test vectors.
- Run the pinned Go SDK as an external differential oracle. Its checkout and
  license stay outside this Swift package.
- Do not commit oracle-generated golden outputs until their provenance and
  copyright status have been reviewed. Compare ephemeral deterministic results
  in the harness meanwhile.

## Reason

Open BSV License v5 requires its notice and license on copies or substantial
portions and restricts the software and derivatives to BSV blockchains. Mixing
copied fixtures into an otherwise MIT test bundle would create a dual-license
boundary that is easy for consumers to misunderstand. Avoiding copied material
keeps the initial package boundary unambiguous while preserving behavioral
parity through differential execution.

## Initial layout

```text
Tests/BSVConformanceTests/Fixtures/
├── README.md
├── Permissive/
│   ├── BitcoinCore/
│   ├── BIPs/
│   ├── NIST/
│   └── Dependencies/
└── Provenance/

Tools/Conformance/
├── README.md
└── go-sdk.lock.json
```

Each committed fixture group carries its original license or notice and a
provenance record. The Go lock records repository, tag, commit, and expected
license without vendoring upstream files.

## Review required before release

Counsel or an authorized project owner should rule on:

- Whether specific numeric/wire-format outputs generated by the Go oracle may
  be committed as uncopyrightable facts or require Open BSV notices.
- Whether the BRC repository will receive a license permitting examples and
  vectors to be copied.
- Whether any planned Swift implementation is adapted closely enough from Go
  source to be derivative rather than independently implemented from behavior
  and specifications.
